# DataTrace 需求定义文档

## 1. 项目定位

**DataTrace** 是一个 **MySQL → MySQL 数据同步系统**，支持全量同步和增量同步。

### 同步范围
- **源端**：MySQL
- **目标端**：MySQL
- **当前版本**：仅支持 MySQL → MySQL

---

## 2. 同步模式

### 全量同步（Full Sync）

| 属性 | 说明 |
|---|---|
| 触发方式 | 用户手动启动 |
| 执行次数 | **一次性** |
| 核心逻辑 | 读取源表全量数据 → 写入目标表 |
| 可暂停 | ✅ 支持 |
| 可停止 | ✅ 支持 |
| 完成状态 | 标记为 `completed` |

**执行步骤**：
1. 初始化目标表结构（建表 / Truncate）
2. 分批读取源表数据
3. 批量写入目标表
4. 上报进度
5. 标记完成

---

### 增量同步（Incremental Sync）

| 属性 | 说明 |
|---|---|
| 触发方式 | 用户手动启动 |
| 执行次数 | **持续运行** |
| 核心逻辑 | 监听 Binlog → 实时同步变更到目标 |
| 可暂停 | ❌ 不支持 |
| 可停止 | ✅ 支持 |
| 完成状态 | **永不停止**，除非用户手动停止 |

**执行步骤**：
1. 连接源 / 目标数据库
2. 检查 Binlog 配置（`binlog_format=ROW`）
3. 记录当前 Binlog 快照点
4. 创建事件队列
5. 启动 Binlog 监听器（异步）
6. 先执行一次全量同步（确保基础数据一致）
7. 标记全量完成，切换到增量消费
8. **持续消费 Binlog 事件** → 写入目标
9. 阻塞等待停止信号

---

## 3. 核心场景：增量同步中的表变更

### 场景一：增量同步中新增一张表

**用户需求**：正在增量同步，源库新增了一张表，需要同步到目标端，且**任务不能中断**。

**当前系统行为**：
- 当前系统**不支持**增量同步中动态新增表
- 新增的表不会被 Binlog 监听器捕获（因为监听器启动时已固定表列表）

**需要新增的能力**：
1. 用户通过 API 更新任务配置，添加新表
2. 系统对新表执行一次全量同步
3. 将新表加入 Binlog 监听的过滤列表
4. 后续 Binlog 事件自动覆盖新表

### 场景二：增量同步中删除一张表

**用户需求**：正在增量同步，源库删除了一张表。

**需要新增的能力**：
1. 用户通过 API 更新任务配置，移除某张表
2. 系统从 Binlog 监听的过滤列表中移除该表
3. **不再同步该表的任何事件**
4. 不删除目标端已同步的数据（用户可选择是否清理）

---

## 4. 数据流

```
MySQL 源库
    │
    ├── Binlog 监听器 ──→ 事件队列 ──→ 增量消费者 ──→ MySQL 目标库
    │
    └── 数据读取器 ──→ 全量同步引擎 ──→ MySQL 目标库
```

---

## 5. 错误处理策略

### 全量同步

| 策略 | 行为 |
|---|---|
| `skip` | 跳过失败表，继续下一表 |
| `pause` | 遇到错误暂停所有 Worker |

### 增量同步

| 策略 | 行为 |
|---|---|
| `skip` | 跳过失败事件，记录错误日志，继续消费 |
| `pause` | 遇到错误暂停消费，任务标记为 paused |

### 断线重连

- Binlog 连接断开 → 自动重连，从上次快照点继续
- 目标库连接断开 → 消费暂停，自动重连后继续
- Redis 断开 → 降级到内存队列

## 6. API 设计

### 任务管理

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/tasks` | 任务列表 |
| `POST` | `/api/v1/tasks` | 创建任务 |
| `PUT` | `/api/v1/tasks/:id/config` | 更新配置（含表变更） |
| `DELETE` | `/api/v1/tasks/:id` | 删除任务 |
| `POST` | `/api/v1/tasks/:id/start` | 启动任务 |
| `POST` | `/api/v1/tasks/:id/stop` | 停止任务 |

### SSE 推送

| 端点 | 事件 | 说明 |
|---|---|---|
| `/stream/detail` | `task_detail` | 任务状态变更 |
| `/stream/progress?target_id=&database=` | `progress` | 进度更新 |
| `/stream/logs?category=` | `log` | 日志推送 |

### 关键约束

1. **`PUT /config` 在增量运行中不允许修改已同步的表列表**
   - 新增表：允许，后台对新表做全量同步后加入监听
   - 删除表：允许，从监听列表移除
2. **`GET /tasks/:id/config-view` 返回实时表结构检测**
3. **进度 SSE 只推送增量，不轮询**
